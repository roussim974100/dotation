## Conventions critiques — NE PAS OUBLIER

### 1. `_KNOWN_TABLES` dans `database.py`
Toute nouvelle table utilisée avec `ensure_column()` doit être ajoutée à la whitelist `_KNOWN_TABLES`. Sinon : `ValueError: Table inconnue`.

### 2. `slugify_field_key()` — DANGER
Dans `utils.py`, convertit en minuscules (`numeroSerie` → `numeroserie`).  
**Usage autorisé** : créer une nouvelle clé depuis un label utilisateur.  
**Interdit** : lookup dans un `fields{}` existant. Utiliser `field_values_lower` pattern (lookup case-insensitive) pour les clés existantes.

### 3. `persist_form()` retourne `{"summary": {"id": ...}, "data": ..., "items": [...]}`
Ne jamais faire `form_data["id"]` — c'est `form_data["summary"]["id"]`.

### 4. Bootstrap 5 — `getOrCreateInstance` pas `getOrCreate`
`bootstrap.Modal.getOrCreate` n'existe pas. C'est `bootstrap.Modal.getOrCreateInstance`.  
**Source d'un bug passé** : le bouton "Ajouter co-utilisateur" ne faisait rien.

### 5. `generate_id()` exige un préfixe
`generate_id("pool")`, pas `generate_id()` seul.

### 6. Endpoint session : `/api/session` pas `/api/me`
`/api/me` n'existe pas → 404. Toujours `/api/session` pour récupérer l'utilisateur courant côté JS.

### 7. CSRF token dans la réponse de `/api/session`
Le token est dans `data.token` (pas `data.csrf_token`). Defensive : `data.token || data.csrf_token`.

### 8. Champs ressource en camelCase dans `fields{}`
`numeroSerie`, `nomTelephone`, `marque`, `modele`, `imei`, `nomPoste`, `nomTablette`.  
Stockés tels quels dans `payload_json`. Ne jamais slugifier pour lookup.

### 9. `ensure_column()` pour les migrations
Pas de framework de migration. `ensure_column(conn, table, col, sql)` dans `init_db()`.  
Toute nouvelle colonne doit y être déclarée + ajoutée à `_KNOWN_TABLES`.

- **Section #section-retraits** : picker source + checkboxes (état + notes) + signature pad inline
- Signature inline retraits (pas de lien externe) → PDF "Fiche de retraits"
- `getFormData()` + `populateForm()` : intègrent payload.retraits complètement
- createSignaturePad() réutilisable pour les deux pads (attribution + retraits)
- **Tests** : 6 tests d'intégration ✅ tous passants (test_retraits_v311.py)

**Traçabilité** : 
- dotation_items du source : `returned=1, returned_at, return_condition, notes`
- payload_json du source : `restitution.items[key]` mis à jour avec state/notes/returnedAt
- audit_event sur dossier source avec ref au dossier mise_a_jour
- Aucune régression : 322 tests backend ✅ passants

## Pièges récurrents / lessons learned

- **Luc Petit (1776804610025)** : dossier de test co-user. L'ordinateur a été injecté directement en DB (script `_inject_resource_into_form`) car le modal ne fonctionnait pas au moment où il a été ajouté au pool. Le dossier propriétaire (1776804605909 = Sophie Bernard) avait `sharedWith: []` → désync. Fix : `get_form()` reconstruit depuis DB maintenant.

- **`shared_pool_items` jamais peuplé** : bug découvert en démo — `sync_shared_pools_for_form` ne créait pas les items. Fix : ajout du bloc upsert avec `marque/modele/numeroSerie`.

- **Dual declaration `_fieldSuggestCache`** : `app.js` et `app-suggestions.js` déclaraient tous les deux `const _fieldSuggestCache`. Fix : retirer de `app.js`, `app-suggestions.js` est l'unique propriétaire.

- **Bootstrap Modal API** : sur form.html, Bootstrap JS bundle doit être chargé explicitement (pas via CDN auto). Sans lui, `bootstrap.Modal` est undefined.

- **`/login.html` vs `/login`** : la route Flask expose `/login` (sans .html). Rediriger vers `/login` uniquement.
